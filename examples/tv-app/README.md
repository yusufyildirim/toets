# toets TV example app

One React Native codebase ([react-native-tvos](https://github.com/react-native-tvos/react-native-tvos) on Expo) for Android TV, tvOS and web ([react-native-web](https://necolas.github.io/react-native-web/)). toets dogfoods every platform against it.

Side menu, home with rails of cards, details, a player and settings. Stable test IDs and focus behaviors are listed in [TESTIDS.md](./TESTIDS.md).

## Build and run

From this folder (`pnpm install` at the repo root first):

| Command              | Result                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------- |
| `pnpm build:web`     | Static web bundle in `dist/web`                                                        |
| `pnpm serve:web`     | Serves `dist/web` on http://localhost:8090 and the API on http://localhost:8091        |
| `pnpm build:android` | Debug APK `dist/android/toets-tv-debug.apk` (package `dev.toets.example`)              |
| `pnpm build:tvos`    | tvOS Simulator app `dist/tvos/toetsTV.app` (bundle ID `dev.toets.example`, macOS only) |
| `pnpm api`           | The JSON API alone on port 8091                                                        |
| `pnpm start`         | Metro dev server (`expo start`) for live development                                   |

Native builds embed the JS bundle, so they run without Metro: the APK is a debug build, the tvOS app a Release build (Debug simulator builds always load JS from Metro). `android/` and `ios/` are generated by `expo prebuild --clean` on every build ([continuous native generation](https://docs.expo.dev/workflow/continuous-native-generation/)): change `app.config.ts`, never the generated folders. `ANDROID_ABIS` (default `arm64-v8a,x86_64`) selects the APK's ABIs.

The app calls the API at `http://localhost:8091` (`EXPO_PUBLIC_API_URL` at build time overrides it). Native apps need it on the device's `localhost`: the tvOS simulator shares the host network; on an Android emulator run `adb reverse tcp:8091 tcp:8091`.

## toets SDK

The app embeds [`@toets/sdk-react-native`](../../packages/sdk-react-native/docs/react-native.md). Everything toets-specific lives in [`src/toets`](./src/toets); the rest of the app imports from there, never from toets packages.

- **Start:** [`src/toets/start.ts`](./src/toets/start.ts) is the entry file's first import, so the SDK is in place before any app module runs. It is inert unless toets launched the app.
- **Payload:** web reads `?__toets=`, tvOS the `-__toets` launch argument, Android the `__toets` intent extra, handed to JS by a `getLaunchOptions()` override that [`app.config.ts`](./app.config.ts) adds to `MainActivity`.
- **Mocking:** the API client routes to `getLaunchPayload()?.mockUrl`, keeping the path, with the real origin in the `x-toets-original-origin` header. It works with and without the SDK session (black-box runs). Settings shows the API in use.
- **Launch states:** `details:<id>` and `player:<id>`; flag `autoplay` (boolean). See [`launchStateActions`](./src/navigation/navigation.ts).
- **Media:** the player reports to the `media` domain as `main` through `useToetsMedia` ([`src/toets/media.ts`](./src/toets/media.ts) bridges expo-video's events).
- **Idle:** a pending focus request (a screen taking or restoring focus) counts as a navigation transition.
- **Production builds:** only e2e builds (`TOETS_E2E=1`, the build scripts' default) bundle the SDK and the Android glue; any other bundle gets the no-op module ([`metro.config.ts`](./metro.config.ts)). `TOETS_E2E=0 pnpm build:android` builds without it.

## E2E tests

The cross-platform suite lives in [`e2e`](./e2e) ([`playwright.config.ts`](./e2e/playwright.config.ts), page objects in `e2e/pages`). Build the target first, then:

```sh
pnpm e2e --project=web                     # also: web-blackbox
TOETS_DEVICES=emulator-5554 pnpm e2e --project=android-tv   # running emulator; without it toets manages one
TOETS_DEVICES=<simulator-udid> pnpm e2e --project=tvos      # booted simulator; without it toets manages one
```

The suite starts the API and serves the web build (`node server/main.ts web`); native projects need only the API, so they run without a web build.

`fire-tv` runs the deep link tests through the Fire TV content intent (`TOETS_DEVICES=emulator-5554 pnpm e2e --project=fire-tv`). `*-blackbox` projects run the same tests without the SDK session; tests needing an SDK capability are skipped with the reason, everything else must pass unchanged. The parity matrix lands in `toets-report/parity.md`.

## Deep links

`toetstv://details/<itemId>` (and `toetstv://player/<itemId>`) open a title, cold or while running ([`useDeepLinks`](./src/navigation/useDeepLinks.ts), [`deepLinkActions`](./src/navigation/navigation.ts)). The scheme is registered on every platform by [`app.config.ts`](./app.config.ts); web routes the same paths (`/details/<itemId>`). For Fire TV, `app.config.ts` also adds a content intent (`dev.toets.example.OPEN_DETAILS` with the string extra `contentId`) that `MainActivity` rewrites into the link, cold (`onCreate`) and running (`onNewIntent`). The `fire-tv` project runs [`deep-links.spec.ts`](./e2e/deep-links.spec.ts) with its `deepLink` mapper translating the canonical link into that intent.

## Media keys

The player handles play/pause, play, pause, fast forward, rewind and stop in JS ([`useMediaKeys`](./src/remote/useMediaKeys.ts)). On Android, React Native does not consume keys, so the system would also hand them to expo-video's media session (play/pause toggling twice, stop resetting the player). [`modules/media-keys`](./modules/media-keys) consumes them after JS has seen them.

## Focus

The native focus engines (tvOS, Android TV) move focus; `TVFocusGuideView autoFocus` gives rails and the menu their focus memory. On web, [`spatialNavigation.web.ts`](./src/focus/spatialNavigation.web.ts) implements the same arrow-key navigation and group memory. Screens own initial focus and restore the focused element on back ([`FocusScope`](./src/focus/FocusScope.tsx)).

Traps worth knowing:

- Rails and the menu trap up/down (`FocusGroup trap`), so the menu is only reached with left.
- Android TV: a horizontal `FlatList` clips offscreen cards out of the view tree and its arrow-key scrolling can scroll without moving focus. Rails set `removeClippedSubviews={false}` and `snapToAlignment="item"` (react-native-tvos), so every press moves focus.
- tvOS: the focus engine only enters a focus guide that overlaps the focused item on the other axis. The menu's item group fills the menu's height and the home group spans hero and rails, so left from any rail reaches the menu and right from any menu item restores the last card.
- tvOS: React Native joins an accessible view's child texts into its label (`Northern Lights, 2025 · Drama`), and XCUITest flattens plain views with a `testID` (`rail_trending`, `screen_home`) into childless elements. Black-box tests on tvOS match card text with `toContainText`, and scope into rails or assert focus within them only with the toets SDK connected.
- Screens owning their focus restore it in JS (`FocusScope`) instead of relying on native focus guides alone, so it also works when the element that had focus re-mounts (e.g. after a retry).
